## 宿題

- 取り組んだレベル：基礎 
- やったこと：同じ質問を３回実行し、その後app/tools.py の search_glossary の docstring だけを書き換えて、同じ質問をまた3回実行して、回答の比較を実施
- 結果：
### 変更前（基準）：「LoRAとQLoRAの違いは？」を3回
- 3回とも search_glossary({'query': 'LoRA'}) と search_glossary({'query': 'QLoRA'}) が呼ばれた
- 3回とも requests=2, tool_calls=2（1回目の LLM 呼び出しで2つの検索を同時に依頼している）
- input_tokens は毎回1502、output_tokens は224〜236
- 回答の内容は用語集の定義と合っていた。言い回しや「第N回」の書き方は毎回違った
  （例：「第2回（第2回）」と重複した回もあった）

#### 変更後：docstring を「用語を1つだけ入れる（例: "LoRA"）」から「用語をまとめて入れる（例: "LoRA QLoRA"）」に変えて、同じ質問を3回
- 3回とも search_glossary({'query': 'LoRA QLoRA'}) が1回だけ呼ばれた
- 3回とも requests=2, tool_calls=1
- input_tokens は毎回1197（変更前より約300少ない）、output_tokens は220〜278
- 回答の内容は変更前と同じく用語集の定義と合っていた。
  QLoRA の説明も定義どおりだったので、1回の検索で LoRA と QLoRA の両方が見つかったと考えられる
- 「第N回」は3回とも「（関連する回：第2回）」と同じ書き方だった

#### 比較
|               | 変更前                        | 変更後                      |
|---            |---                            |---                         |
| ツール呼び出し | 'LoRA' と 'QLoRA' を別々に検索 | 'LoRA QLoRA' をまとめて検索  |
| tool_calls    |               2               |               1            |
| requests      |               2               |               2             |
| input_tokens  |             1502              |             1197            |
| 回答の内容      |         用語集どおり          |           用語集どおり        |

- 気づき・疑問：
docstring の「1つだけ」「まとめて」という言葉と例だけで、モデルの引数の作り方が変わった
検索の回数（tool_calls）が減っても、LLM の呼び出し回数（requests）については変わらなかった
まとめた検索がうまくいったのは、tools.py の部分一致の作りのおかげで、docstring を変えるときはプログラム側の作りとも合っているかを確かめる必要がある
疑問：検索結果は最大3件（MAX_RESULTS = 3）なので、3つ以上の用語をまとめて聞くと、取りこぼしが出る可能性がある
